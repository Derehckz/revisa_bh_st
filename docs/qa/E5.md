# QA — Épica E5 — Estado de sincronización Excel↔PostgreSQL

## Alcance del cambio
- `lib/sync_status.py` (nuevo): `period_sync_status(year, month) -> dict`
  - Lee KPIs del Excel vía `stage_operations.period_summary(year, month)`
    (`total_rows`, `solicitud_exists`).
  - Intenta contar boletas en PostgreSQL para el mismo período
    (`db.models.Periodo` + `db.models.Boleta`, vía `db.session.SessionLocal`).
  - Contrato de salida: `{"status": "ok"|"degraded"|"unknown", "message": str,
    "details"?: dict}`.
    - `unknown`: no se pudo leer el Excel, no se pudo consultar PostgreSQL, el
      `Periodo` no existe en BD, o no hay datos en ninguna de las dos fuentes.
    - `degraded`: existe `Periodo` en BD pero el conteo difiere
      significativamente del total de filas del Excel (umbral: `max(3, 5%
      del mayor de los dos totales)`).
    - `ok`: ambas fuentes coinciden (dentro del margen de redondeo).
  - Nunca lanza excepciones: cualquier error se traduce en `status="unknown"`.
- `lib/stage_operations.py::period_overview(...)`: agrega la clave
  `sync_status` al payload (calculado de forma perezosa/segura; si
  `sync_status` explota por cualquier motivo, se degrada a `unknown` sin
  romper el resto del overview).
- `frontend/src/shared/api/types.ts`: nuevo tipo `SyncStatus` y campo opcional
  `sync_status` en `PeriodOverviewResponse`.
- `frontend/src/features/operacion/period-toolbar.tsx`: nuevo badge
  (`SyncStatusBadge`) que solo se muestra cuando `sync_status.status !== "ok"`
  (texto ámbar para `degraded`, gris para `unknown`), con el mensaje completo
  en el `title` (tooltip).
- `frontend/src/features/operacion/page.tsx`: pasa `overview.data?.sync_status`
  al `PeriodToolbar`.

## API
- [ ] `GET /operations/period/overview?year=2026&month=Julio` incluye
      `sync_status: {status, message, details}` en la respuesta.
- [ ] Con PostgreSQL caído/inaccesible, `sync_status.status == "unknown"` y el
      resto del overview sigue funcionando (no debe romper la pantalla).
- [ ] Con un período recién creado en Excel pero sin sincronizar en BD
      (`Periodo` inexistente), `sync_status.status == "unknown"`.
- [ ] Con conteos alineados (Excel y BD con el mismo total), `status == "ok"`
      y no aparece badge en la UI.
- [ ] Forzando una diferencia grande entre Excel y BD (p.ej. truncando la BD
      de pruebas), `status == "degraded"` y aparece el badge ámbar.

## Frontend
- [ ] Al seleccionar un período con `sync_status` distinto de `ok`, aparece el
      badge debajo del selector de mes, sin romper el layout existente.
- [ ] Con `sync_status` `ok` o ausente, no aparece ningún badge (comportamiento
      idéntico al actual).

## Casos borde
- [ ] Excel abierto por otro proceso (`PermissionError` al leer) → `unknown`
      con mensaje descriptivo, sin excepción no controlada.
- [ ] Mes con 0 filas en Excel y 0 boletas en BD (mes realmente vacío) →
      `unknown` (evita falso "ok" por comparar 0 con 0 sin contexto).
